# 初期配置について
ゲームの最初に赤駒と青駒の配置を設定することができる。
設定可能な空間は自陣側の中央寄り2行4列（計8マス）である。

* 1アクションで初期配置を決定する。
* 配置は全部で (\binom{8}{4}=70) 通りとする。
* 配置IDとして0〜69を使用する。
* 赤駒4個の配置を決定し、残り4マスを青駒とする。
* 4列には左から0〜3の列番号を付ける。
* 各列では前側と後ろ側の2マスを区別する。

### ID 0〜15：各列に赤駒が1個ずつ

配置IDの下位4bitを各列の配置に対応させる。

* bit 0：列0
* bit 1：列1
* bit 2：列2
* bit 3：列3
* bitが0の場合、その列の前側を赤駒とする。
* bitが1の場合、その列の後ろ側を赤駒とする。

したがって、配置数は (2^4=16) 通りとなる。

### ID 16〜63：赤駒が2個の列と青駒が2個の列が1つずつ

`local_id = id - 16`とし、次のように分解する。

* `pair_id = local_id / 4`
* `mixed_bits = local_id % 4`

`pair_id`は、赤駒が2個ある列と青駒が2個ある列の順序付きペアを表す。

ペアは、赤駒が2個ある列を左から優先し、同じ赤列の中では青駒が2個ある列を左から順に並べる。

順序は次の通りとする。

```text
(赤列, 青列)
(0,1), (0,2), (0,3),
(1,0), (1,2), (1,3),
(2,0), (2,1), (2,3),
(3,0), (3,1), (3,2)
```

残り2列には赤駒と青駒を1個ずつ配置する。

残った列を左から順に並べ、`mixed_bits`の各bitを対応させる。

* bitが0の場合、前側を赤、後ろ側を青とする。
* bitが1の場合、前側を青、後ろ側を赤とする。

配置数は (12\times 2^2=48) 通りとなる。

### ID 64〜69：赤駒が2個ある列が2つ

赤駒が2個ある列の組合せを、次の辞書順で割り当てる。

```text
64: (0,1)
65: (0,2)
66: (0,3)
67: (1,2)
68: (1,3)
69: (2,3)
```

指定されなかった残り2列は、上下とも青駒とする。

配置数は (\binom{4}{2}=6) 通りとなる。


**64〜69：赤駒が2個の列が2つ**
  - 赤駒が2個の列を4列から2列選ぶ
  - 4C2 = 6通り
  - 辞書順での優先順序
    - 左>右

## GeisterPhaseFrag
- ゲームが配置フェイズか対戦フェイズかを表すenum
  - GeisterPhaseFrag::SelectPhase = 配置フェイズ
  - GeisterPhaseFrag::PlayPhase = 対戦フェイズ
## GeisterState
- 今の状態が配置フェイズか対戦フェイズか GeisterPhaseFrag GetGamePhase() で取得可能
- 配置フェイズの際はDoApplyAction(int action_id)が配置のための関数に切り替わる
  - action_idはOnePlayerBoardで返された合法手の中から選ばれる
- 対戦フェイズになった時点で駒移動のための関数にDoApplyActionが切り替わる
- 今の状態が対戦フェイズか配置フェイズかを0,1で表し、盤面表現tensorに入れておく
